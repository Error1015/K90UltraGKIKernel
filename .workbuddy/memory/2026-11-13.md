# 2026-11-13

## 重做 K90UltraGKIKernel —— 定位并修复"刷进去卡 logo"的真正根因

用户反馈"构建能出包，刷进去起不来"，要求照搬已验证的上游方案重做。

### 根因（终于确定的硬结论）
这台机器的 **boot 分区不是裸内核**，而是整体：
```
[0,4096) boot header v4 (header_size=1584, ramdisk_size=0)
[4096, 4096+kernel_size) 内核 Image
round_up(kernel_size 末尾) → vbmeta blob (2368B, "AVB0")
末尾 64 字节 AVB footer ("AVBf"): original_image_size / vbmeta_offset / vbmeta_size
文件总长 100663296 (96MB 分区大小)
```
换内核后必须把 vbmeta 重定位到新的页对齐位置 + 重写 footer 三个字段 + 保持 96MB。
否则 footer 指向被新内核覆盖的旧偏移 → AVB 校验失败 → 卡 logo、不 panic、不重启。

旧产物两条都踩坑：AK3 只写内核；`boot-k90-custom.img` 只改了 kernel_size（37MB，无 vbmeta 无 footer）。
叠加当时设备还是 LKM 模式（init_boot 里有 kernelsu.ko），双重卡死。

佐证：同机型已验证仓库 wjljh/xiaomi_kernel_for_warsaw_sukisu_susfs 明确写了同一套布局与处理方式。

### 原厂镜像实测（本机 boot.img，OS 4.0.8.0）
- kernel_size 36801024；ramdisk_size 0；vbmeta_offset 36823040；vbmeta_size 2368
- 版本串 `6.6.118-android15-8-g0908354dac1b-ab16143355-4k`（4.0.0.14 是 gc4127a25dcf3，sublevel 同为 118）
- 内嵌 IKCONFIG 可解出完整 .config（7756 行）；LTO_NONE=y、TRIM_UNUSED_KSYMS=y、
  UNUSED_KSYMS_WHITELIST="abi_symbollist.raw"（Kleaf 生成，make 构建没有 → 必须关 TRIM）

### 新实现（commit fee33d7，已 push 到 origin/master）
- 构建：`make ARCH=arm64 LLVM=1 O=out Image`（放弃 Kleaf/Bazel）
- 配置：直接用原厂 .config（configs/warsaw_defconfig）+ base.fragment（TRIM=n、LOCALVERSION_AUTO=n）
- 源码：repo sync common-android15-6.6-lts，再按版本解析 ACK tag 钉到 refs/tags/...
- root：SukiSU-Ultra v4.3.0 + susfs4ksu 50_add + 仓库内置的移植补丁 patches/susfs-for-sukisu-v4.3.0.patch
- 打包：project/pack.py（AVB 感知，输出 96MB）；模板 firmware/boot-template.bin 仅 6.4KB（header+vbmeta）
- 验收：project/verify.py 三重校验（结构 / 版本串 / 内嵌配置），不过不发布
- 工作流：vanilla + sukisu 两条并行，只出 fastboot 可刷的 boot.img，不再产 AK3
- 旧流水线整体移到 legacy/，设备侧诊断脚本留在 tools/
