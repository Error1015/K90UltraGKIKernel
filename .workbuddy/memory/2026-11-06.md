# 2026-11-06

## K90UltraGKIKernel 仓库搭建

目标：为 Redmi K90 Ultra（warsaw / SM8750 / 6.6.57）做 GitHub Actions 构建 GKI 内核的仓库，
支持 KernelSU 系 root + SUSFS 及一系列功能开关。

### 关键调研结论（可复用）
- 小米 `MiCode/Xiaomi_Kernel_OpenSource` 分支 `warsaw-w-oss` 是 Qualcomm kernel_platform 里的
  `msm-kernel` 部分，根目录 Makefile 是 6.6.57；`msm_kernel_la.bzl` 里 `base_kernel = "//common:kernel_aarch64"`，
  说明设备 boot 的内核主体来自 GKI（ACK），小米侧只编 vendor 模块。→ 自建 GKI 是可行路线。
- ACK 没有 `android16-6.6` 分支，Android 16 的 6.6 设备仍走 `android15-6.6`（manifest 分支
  `common-android15-6.6-<yyyy-mm>` / `-lts`）。
- 内核 `scripts/config` 的 `checkarg` 会自动剥离 `CONFIG_` 前缀，带不带前缀都能用；
  `--enable/--module/--disable` 分别写 `=y` / `=m` / `# ... is not set`，字符串用 `--set-str`。
- SUSFS 6.6 补丁（susfs4ksu `gki-android15-6.6`）只含 27 个内核文件的 diff + `fs/susfs.c`、
  `include/linux/susfs*.h`；Kconfig 符号来自 root 管理器（tiann 需额外打 `10_enable_susfs_for_ksu.patch`）。
- 6.6 上 SUSFS 的四个固定坑：base.c 缺 `dma-buf.h`、memory.c 缺 `zswap.h`、`VMA_PAD_START` 宏缺失、
  `show_fdinfo` 3 参 vs `fanotify_fdinfo` 2 参。

### 实现
- `.github/workflows/build.yml`：18 个 workflow_dispatch 输入（root 管理器 / 9 个功能开关 / 页大小 /
  manifest 分支 / tag / 版本对齐 / brand / 是否发 Release），单 job。
- `scripts/{lib,prepare,build,package}.sh` + `scripts/py/{version_pin,susfs_66_compat}.py`
- `config/{base,root/*,features/*}.config`
- 用真实 `scripts/config` 与假补丁做过本地验证：写配置、回读校验、补丁成功/失败路径、compat 幂等性均通过。
- 依赖外部仓库：susfs4ksu(gitlab)、WildKernels/kernel_patches、maxsteeel/nomount、
  vc-teahouse/Baseband-guard、ravindu644/Droidspaces-OSS、WildKernels/AnyKernel3(gki-2.0)。

### 待办 / 风险
- 未在真实 runner 上跑过完整构建（本地无法 repo sync），首次 push 后需实测一次。
- SUSFS 补丁与最新 ACK sublevel 可能漂移，失败会落到 `patch-rejects` 工件，需要补 compat。

## 产物体检（Release k90ultra-bakasu-6.6.118-...-4k）

用户仓库：github.com/Error1015/K90UltraGKIKernel，已构建并上传 Release（BakaSU + SUSFS + NoMount + BBG + BTF，4k）。

- Image 38,464,000 字节；arm64 头正常（magic ARMd、code1 是 b 分支、flags=0xa → LE + 4K + PHYS_BASE）。
- 版本 6.6.118-android15-8-maybe-dirty-4k；内嵌 IKCONFIG 可解出完整 .config（214KB）。
- 关键配置：MODVERSIONS=y / KSU=y / KPROBES=y / KSU_SUSFS + 9 子项 / NOMOUNT / BBG(在 CONFIG_LSM 里) /
  DEBUG_INFO_BTF / FUSE_BPF / 4K_PAGES / MODULE_SIG_FORCE=n；binder+binderfs+ashmem+seccomp+selinux 齐全。
- **重要结论**：ACK 6.6 的 `same_magic()`（kernel/module/version.c）在有 CRC 时只比较第一个空格之后的部分，
  源码注释 "First part is kernel version, which we ignore if module has crcs." → sublevel 差异、-maybe-dirty
  都不影响 vendor 模块加载；真正致命的是符号 CRC 不一致。已据此修正 README/docs 里"版本不匹配会加载失败"的说法。
- 新增：scripts/verify-image.sh + scripts/py/inspect_image.py（离线体检）、.github/workflows/verify.yml（QEMU 启动冒烟）。
- prepare.sh 增加 finalize_tree：提交源码树改动，去掉 uname -r 的 -maybe-dirty。
