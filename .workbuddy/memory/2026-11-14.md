  → 排除 KSU / SUSFS / 附加功能；问题在「我们编出来的内核」或「打包版面」。
- run 24 实测版本串已与原厂逐字节一致（`6.6.118-android15-8-g0908354dac1b-ab16143355-4k`），
  排除 vermagic。

  - 我们缺：`ARCH_WANTS_DYNAMIC_TASK_STRUCT` / `GKI_DYNAMIC_TASK_STRUCT_SIZE` /
    `GKI_TASK_STRUCT_VENDOR_SIZE_MAX=1024` / `MODULE_SCMVERSION` / `ARM64_ERRATUM_4118414` /
    `CMDLINE_LOG_WRAP_IDEAL_LEN`。这些符号在 ACK android15-6.6 里要么没被 select、
    要么不在我们钉的 tag 上 —— 属厂商树独有，靠 .config 打不开（会被 olddefconfig 丢掉）。
  - run 24 其实开着 BBG + NoMount + networking（build-info 当时不记功能集，踩过坑；
    已在 verify.py 补上「附加功能」一行）。

  逐字节一致（cmp 无差异）。

## 两个探针（已生成，待用户刷）

- `dist/diag/probeB.img`：run25 vanilla 内核 **padding 到原厂 kernel_size(36801024)** 后打包。
  与原厂镜像的差异**只在内核区**（header/尾部/vbmeta/footer 全部逐字节相同）。
  → 若挂着 = 我们编出来的内核本身有问题（与版面无关）。
  → 若起来 = 内核没问题，问题在版面/尺寸，解法是「padding 到原厂尺寸」（vanilla 小 204800、
     bakasu 小 8192，都塞得下）。
- `dist/diag/probeA.img`：原厂内核 + 2MB 填充（内核内容不变，版面后移 2MB）。
  → 若挂着 = 版面位移本身不被接受（AVB 摘要/对齐/LK 限制），这才是所有历史产物卡 logo 的共因。
